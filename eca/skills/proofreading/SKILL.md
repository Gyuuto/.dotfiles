# ドキュメント文章校正

指定されたドキュメントに対して、文法・表現・構成・正確性の観点から包括的な校正を行うスキルです。

## Purpose

ドキュメントの品質を向上させ、読み手にとって正確で明確な情報を提供すること。

## Trigger

- ドキュメント（Markdown、テキスト、コードコメント等）の校正を依頼された時
- 公開前の文書レビューが必要となった時
- 文章の明確さや一貫性への懸念が報告された時

## Steps

### 1. 校正対象ファイルの読み込み

対象ファイルを読み込み、全体の構成と内容を把握する。

### 2. 文法・綴りの誤りチェック

- 文法規則に反する表現を特定する
- 綴りミス、入力ミスを探す
- 句読点の使い方を確認する

各誤りについて、元の文と修正後の文を対比させて提示する。

### 3. 表現の一貫性確認

**用語の統一**
- 同一概念に対し複数の表現が使われていないか確認する（例: 「設定」vs「セッティング」）
- 略語の定義が統一されているか確認する

**人称・文体の統一**
- 敬体／常体の混同がないか確認する
- 「私」「わたし」「ボク」などの人称表現が統一されているか確認する
- 図表番号の表記揺れ（「図1」vs「Fig.1」）がないか確認する

### 4. 文章の明確さの改善提案

- 冗長な表現を簡潔に書き直す提案をする
- 代名詞の指す対象が明確か確認する
- 主語・述語の対応関係が明らかなか確認する
- 受動態を能動態に書き替えるべき箇所を提案する

### 5. 論理的構成の確認

- 段落ごとに主旨が明確か確認する
- 段落間の接続が自然か確認する
- 導入・本論・結論の流れが整っているか確認する
- 箇条書きの整合性（並列関係）を確認する

### 6. 専門用語と記述の正確性確認

**専門用語**
- 専門用語が適切な文脈で使われているか確認する
- 初出の専門用語に定義または簡易説明が付いているか確認する
- 用語の定義が文書内で統一されているか確認する

**記述の正確性**
- 数値・日付・統計情報の一貫性を確認する
- URLが正しい形式で記載されているか確認する
- 参照先（図表、セクション、文献）の存在を確認する

### 7. 校正結果のまとめ

以下の項目を含む校正レポートを出力する。

## Output

### 校正結果レポートの形式

```markdown
# 校正レポート

## 1. 文法・綴り

| 行番号 | 元の文 | 修正案 | 理由 |
|--------|--------|--------|------|
| N      | ...    | ...    | ...  |

## 2. 表現の一貫性

| 項目 | 問題箇所 | 修正案 | 備考 |
|------|----------|--------|------|
| 用語 | ...      | ...    | ...  |
| 文体 | ...      | ...    | ...  |

## 3. 明確さの改善提案

| 行番号 | 元の文 | 修正案 | 改善点 |
|--------|--------|--------|--------|
| N      | ...    | ...    | ...    |

## 4. 論理的構成

- [問題なし] / [改善提案あり] 概要と提案内容

## 5. 専門用語と記述

| 項目 | 問題箇所 | 修正案 | 備考 |
|------|----------|--------|------|
| 専門用語 | ...  | ...    | ...  |
| 数値/URL | ... | ...    | ...  |

## 6. 全体の評価

重要な修正: N件 / 軽微な修正: N件 / 提案: N件
```

### 出力ルール

- 修正案は元の意図を損なわない範囲で提案する
- 必須修正と推奨修正を区別して記載する
- 修正理由を簡潔に記載する
- 複数の修正案がある場合は、優先順位を付ける
