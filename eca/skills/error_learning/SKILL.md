# Error Learning — エラー分析と経験の抽出

コードの変更履歴およびユーザとのやり取りを調査し、誤りや問題を抽出する。抽出した知見から新たなルールやスキルを提案する。

## Purpose

- 過去の変更から繰り返されるパターンや根本原因を特定する
- 同様のミスを防止するためのルール・スキルを体系化する
- チームまたはエージェントの学習サイクルを回す

## Trigger

以下のいずれかに該当する場合に適用する：

- リグレッションバグや同様のエラーが繰り返された場合
- 変更履歴やチャットログから教訓を抽出するよう指示された場合
- プロジェクトの品質改善のため、フィードバックループを構築したい場合
- 新たなルールやスキルの作成が必要な場合

## Steps

1. **変更履歴を取得する**

   - `git log` でコミット履歴を確認する
   - `git diff` で変更範囲を把握する（差分の多いコミットを優先）
   - `git blame` で個々の行の変更経緯を追跡する
   - 必要に応じて `git log --oneline` で概要を先に確認する

2. **変更履歴から特定のモードを特定する**

   - **取り消された変更**: revert コミット、削除された行が多いコミット
   - **何度も修正された箇所**: 同じファイル・行に対して複数回のコミットがある箇所
   - **バグフィックス**: commit message に `fix`, `bug`, `hotfix` 等が含まれるもの
   - **大規模リファクタリング**: 変更行数の多いコミット

3. **ユーザとのやり取りを取得する**

   - チャットログ、チケット（issue）、PRのコメントを参照する
   - エラー報告、訂正指示、やり直しの依頼を抽出する
   - 問題解決までのやり取り（試行錯誤の履歴）を記録する

4. **間違えた内容・やり直した内容・トラブルシューティングの内容を抽出する**

   - 変更前後で何が間違っていたかを特定する
   - どの仮定が外れたか、どの前提が誤っていたかを明記する
   - 試行錯誤のパターンを整理する（どこで時間を要したか）

5. **各エラーについて分析する**

   - **根本原因**: なぜこのエラーが発生したのか（欠落していた知識、誤った前提、仕様の未確認等）
   - **修正内容**: 実際にどのような変更が行われたか
   - **再発防止策**: 同様のエラーを繰り返さないための具体的対策

6. **新たなルールまたはスキルとしてgeneralizeする**

   - 抽出した知見から、行動規範（ルール）として表現できるかを評価する
   - 作業手順（スキル）として体系化できるかを評価する
   - 抽象度を適切に調整し、他のコンテキストでも適用可能かを確認する

7. **ルール/スキルの草案を作成する**

   - AGENTS.mdの形式に従って、`rules/` または `skills/` ディレクトリの草案ファイルを生成する
   - ファイル名は `snake_case` を使用する
   - Purpose / Trigger / Steps / Output のセクションを含める

## Output

エラー分析レポート。以下の形式で出力する。

```
# エラー分析レポート

## 概要
- 分析対象: [git logの期間 / 変更セット / チャット期間]
- 分析日時: [日時]
- 抽出エラー数: [数]

---

## エラー分析

### エラー #1: [エラーの要約]

- **根本原因**: [なぜ発生したのか]
- **修正内容**: [実際に行われた変更]
- **再発防止策**: [同様のエラーを防ぐための対策]
- **影響範囲**: [関連するファイル・機能]

---

[同じ形式で他のエラーを列挙]

---

### 出力ルール

- 各エラーは独立したセクションとして記述する
- 根本原因は表面的な原因だけでなく、根本的な要因まで掘り下げる
- 再発防止策は具体的で実行可能な内容とする
- 提案するルール/スキルは、抽出した複数のエラーに共通する知見に基づく
- 提案草案は実際のファイル作成可能な形式で出力する
