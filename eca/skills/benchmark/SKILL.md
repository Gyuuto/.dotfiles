# Benchmark — パフォーマンスベンチマーク

コードやモジュールのパフォーマンスを計測し、結果を定量的に評価するための手順。

## Purpose

- パフォーマンスボトルネックを特定する
- リファクタリング前後の改善効果を数値で検証する
- システムのスループット・レイテンシ・リソース使用量を把握する

## Trigger

以下のいずれかに該当する場合に適用する：

- 処理速度に関する課題が報告された
- リファクタリング前後の性能比較が必要な場合
- システムのキャパシティプランニングのため
- 新規機能のパフォーマンスベースライン測定が必要

## Steps

1. **ベンチマーク対象の機能・モジュールを特定する**

   - 対象範囲を明確にする（関数、クラス、エンドポイント、スレッドなど）
   - 本番環境と同等の負荷条件を定義する
   - 測定項目を決定する（実行時間、メモリ使用量、CPU使用率、I/O待機など）

2. **適切なベンチマークツールを選択する**

   - 言語・フレームワークに応じて以下のいずれかを選択する：
     - Python: `timeit`, `cProfile`, `py-spy`, `pytest-benchmark`
     - JavaScript/TypeScript: `benchmark.js`, `node --prof`
     - Go: `testing.B`, `pprof`
     - Rust: `criterion`
     - Java: JMH, `Async Profiler`
     - C/C++: Google Benchmark, `perf`, `Valgrind/Callgrind`
     - 全般: `wrk`, `ab`, `hey`（HTTPエンドポイント用）
   - 環境変数やプロファイリングフラグを適切に設定する

3. **ベンチマークコードまたはスクリプトを作成する**

   - 測定対象の関数・処理を孤立して実行する
   - 暖機実行（warm-up）を適切に含む
   - ヒートアップ期間を設け、GCやキャッシュ影響を最小化する
   - コード例を以下のように構造化する：

     ```
     # ベンチマークスクリプトの標準構造
     1. 初期化・セットアップ
     2. 暖機実行（一定回数）
     3. 本測定（複数回のイテレーション）
     4. 結果の記録・集計
     ```

4. **結果を収集し、必要に応じて複数回の実行で平均値を求める**

   - 少なくとも3回以上の独立した実行を行う
   - 最大値・最小値・中央値・標準偏差を記録する
   - 外れ値は除外基準を明記の上、除去する
   - 環境要因（他プロセス負荷など）の影響を最小化する

5. **結果を比較可能な形式でまとめる**

   - 以下の要素を含める：

     - 実行環境（OS, CPU, メモリ, ランタイムバージョン）
     - ベンチマーク条件（入力サイズ, 同時接続数, 負荷パターン）
     - 数値結果（表形式で整理）
     - 比較軸（baseline対比, 目標値対比）

   - 表の例：

     | 指標 | 値 | 単位 | 備考 |
     |------|-----|------|------|
     | 平均実行時間 | 12.5 | ms | n=10 |
     | 99パーセンタイル | 28.3 | ms | - |
     | 標準偏差 | 1.2 | ms | - |

6. **改善提案を必要に応じて出す**

   - ボトルネックを特定する（CPUバウンドか、I/Oバウンドか、ロック競合か）
   - 最適化のヒントを提示する：
     - アルゴリズムの改善
     - キャッシュ活用
     - 並列処理の検討
     - 非同期化
   - 改善後の再ベンチマークを提案する

## Output

ベンチマーク結果のサマリーレポート。以下の構成で出力する：

```
# ベンチマークサマリー

## 概要
- 対象：[機能・モジュール名]
- 日時：[実行日時]
- 目的：[測定目的]

## 実行環境
- OS: [OS名とバージョン]
- CPU: [モデルとコア数]
- メモリ: [容量]
- ランタイム: [バージョン]

## ベンチマーク条件
- 入力: [データサイズ・内容]
- 同時実行: [スレッド数・接続数]
- 回数: [イテレーション数]

## 結果
[表形式または数値一覧]

## 比較
- baselineとの差分: [+/- X%]
- 目標値との対比: [達成 / 未達成]

## 改善提案
1. [ボトルネック] → [提案内容]
2. [...]

## 備考
- 測定上の制限事項
- 再現手順（必要に応じて）
```
