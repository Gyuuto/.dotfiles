# テストカバレッジ分析スキル

ソースコードのテストがカバーしていない部分を特定し、追加すべきテストケースを提案するスキルです。

## Purpose

プロジェクトのテストカバレッジを測定・分析し、不足しているテストを明らかにすることで、テスト品質の向上とバグ混入リスクの低減を図る。

## Trigger

以下の条件のいずれかに該当する場合に実行する。

- テストカバレッジの分析を依頼された場合
- 新規機能追加後にテストカバレッジが維持されているかの確認を依頼された場合
- リファクタリング前後でテストカバレッジの変化を確認する場合
- テストケースの追加優先順位を決定する場合

## Steps

1. プロジェクトのテストファイルとソースファイルを特定する
   - テストディレクトリ、テストファイルの命名規則、フレームワークの設定ファイルを調査する
   - ソースファイルの構成を把握する

2. テストカバレッジツールを実行する
   - 言語・フレームワークに応じて適切なツールを選択する
   - 例: Python なら `coverage.py`、JavaScript なら `Istanbul`、Java なら `JaCoCo`
   - 必須フラグ（行カバレッジ、分岐カバレッジ、関数カバレッジ）を有効にして実行する

3. 実行結果からカバレッジ率を収集する
   - 全体のカバレッジ率を算出する
   - モジュール・ファイルごとのカバレッジ率を抽出する
   - 行、分岐、関数の各メトリクスを記録する

4. 未テストのモジュール、関数、分岐を特定する
   - カバレッジ率が0%のファイル・関数を探す
   - 分岐カバレッジが不十分な箇所を抽出する
   - テストコードが存在するがassertion不足の箇所を特定する

5. 各未テスト箇所について、どのテストケースが不足しているかを分析する
   - 関数のシグネチャ、ドキュメント、使用箇所から期待される動作を推定する
   - 境界値、異常系、エッジケースの不足を評価する
   - 依存関係からモックが必要な箇所を特定する

6. テストケースの追加提案を優先度付きでリスト化する
   - 優先度: High（重要な機能、バグの起こりやすい箇所）、Medium（標準的な機能）、Low（補助的な処理）
   - 各提案に該当するファイル、関数、想定されるテストケースを明記する
   - 既存テストとの重複がないか確認する

7. カバレッジレポートをまとめる
   - 全体カバレッジ率、未テスト箇所一覧、テスト追加提案を1つのレポートに統合する
   - 改善目標の閾値を提示する（任意）

## Output

以下の情報を含むカバレッジレポートを出力する。

- 全体のカバレッジ率（行、分岐、関数の各メトリクス）
- モジュール・ファイルごとのカバレッジ率一覧
- 未テスト箇所の一覧（ファイルパス、関数名、未テストの種類）
- 追加すべきテストケースの提案リスト（優先度、対象箇所、提案テストケースの概要）
- 改善に向けた具体的なアクション項目（任意）
