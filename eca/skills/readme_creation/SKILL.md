# README Creation

プロジェクトの README.md を作成するためのスキル。プロジェクトの概要、インストール方法、使用例、構成などを整理したドキュメントを生成します。

## Purpose

新規または既存のプロジェクトに対して、標準的な構造を持つ README.md を自動生成し、プロジェクトへの参画障壁を下げます。

## Trigger

- プロジェクトのルートディレクトリに README.md が存在しない場合
- プロジェクトの開発が初期段階に入り、ドキュメントの作成が必要となった場合
- 既存の README.md が古く、最新の状態に更新する必要がある場合

## Steps

1. **プロジェクトのディレクトリ構造を把握する**

   ルートディレクトリを再帰的に走査し、主要なファイル・ディレクトリを把握します。

2. **AGENTS.md や既存ドキュメントからプロジェクト概要を抽出する**

   ルートディレクトリに `AGENTS.md`、`CONTRIBUTING.md`、`CHANGELOG.md` などが存在する場合はそれらを読み取り、プロジェクト名・概要・目的を抽出します。存在しない場合はディレクトリ名やファイルの内容から推測します。

3. **依存関係とインストール手順を確認する**

   以下のファイルが存在する場合はその内容を確認し、必要な依存パッケージとインストール手順を特定します。

   - `package.json` (Node.js)
   - `requirements.txt` / `pyproject.toml` (Python)
   - `Cargo.toml` (Rust)
   - `pom.xml` / `build.gradle` (Java)
   - `Gemfile` (Ruby)
   - `go.mod` (Go)

4. **主要な API または使用方法を確認する**

   ソースコードの主要なエントリーポイントや公開 API を確認し、代表的な使用例を抽出します。

5. **必須セクションを基に README.md を作成する**

   以下のセクションを含めて README.md を生成します。

   - **プロジェクト名と概要** — 1〜2 文でプロジェクトの目的と機能を説明
   - **インストール方法** — 依存パッケージのインストール手順を記載
   - **使用方法** — コード例付きで基本的な使い方を説明
   - **構成** — ディレクトリ構造の簡単な説明
   - **テスト方法** — テストの実行方法とコマンドを記載
   - **貢献方法** （任意）— 貢献の手順、コントリビューションガイドへのリンク
   - **ライセンス** （任意）— 使用されているライセンスを記載
   - **連絡先** （任意）— メンテナやコミュニティへの連絡先

6. **コード例が具体的で理解しやすいか確認する**

   記載するコード例が実際の動作を正しく表しているか、変数名や関数名が実装と一致しているか確認します。必要に応じて補足説明を追加します。

7. **ユーザが最初につまづきそうな点を想定して補足説明を追加する**

   環境構築でよく発生する問題（OS 依存、Node/Python のバージョン要件、環境変数の設定など）について、FAQ やトラブルシューティングセクションを追加します。

## Output

`README.md` ファイル（マークダウン形式）。

必須コード例と構造化されたセクションを含みます。出力イメージは以下の通りです。

```markdown
# プロジェクト名

プロジェクトの簡潔な概要を1〜2文で記載します。

## インストール

```bash
# インストールコマンドを記載
```

## 使用方法

```python
# 具体的なコード例を記載
```

## 構成

```
.
├── src/          # ソースコード
├── tests/        # テストコード
└── docs/         # ドキュメント
```

## テスト

```bash
npm test
```
