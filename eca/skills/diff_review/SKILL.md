# Diff Review

PRや変更差分をレビューするスキル。変更の意図、コード品質、ルール準拠を検証し、フィードバックを生成する。

## Purpose

レビュー対象の変更が品質・一貫性・安全性を満たしているかを体系的に評価し、改善すべき点を明確に提示する。

## Trigger

- PR（Pull Request）のレビューを依頼された場合
- 変更差分（diff）の検証を指示された場合
- コード変更の影響評価が必要になった場合

## Steps

1. diffまたは変更対象ファイルを読み込む
2. 変更の意図と影響範囲を確認する
3. チェックリストに基づいてレビューする
4. 問題点をリスト化し、優先度をつけるとともに改善提案を出す

## Checklist

変更検証時に以下の項目を網羅的に確認する。

- **変更の意図と一貫性**
  - 変更が意図した機能・修正に合致しているか
  - 関連箇所への変更も漏れなく行われているか
  - 既存の動作と矛盾していないか

- **ルール準拠**
  - プロジェクトのドキュメント（AGENTS.md等）との整合性
  - 命名規則、インデント、ファイル構成の統一性
  - テストケースの有無・適切なカバレッジ

- **機密情報の混入**
  - APIキー、パスワード、トークン等のハードコーディング
  - 内部URL、IPアドレス、個人情報

- **命名規則とコードスタイル**
  - 変数・関数・クラスの命名が規則に沿っているか
  - 可読性を損なう複雑な構造になっていないか

- **不要なコードやコメントの除去**
  - 死んだコード（未使用）が残っていないか
  - 削除予定コードのコメントアウトが残っていないか
  - 意味のないデバッグ用コメントがないか

- **エラーハンドリングの適切さ**
  - 例外ケースが適切にキャッチされているか
  - エラーメッセージが有用か
  - リソースリーク（ファイルオープン等）のリスクがないか

優先度分類:

| 優先度 | 意味 |
| --- | --- |
| `blocker` | 修正必須。マージ不可 |
| `major` | 修正推奨。実害が発生する可能性あり |
| `minor` | 改善提案。品質向上のため推奨 |

## Output

レビュー結果を以下の形式でレポートする。

```
## レビュー結果

### 全体評価
[変更の概要と品質を簡潔に評価]

### 問題点一覧

#### [優先度] 問題の要約
- 該当箇所: ファイルパス:行数
- 説明: 問題の具体的な内容
- 提案: 修正案または改善方法

### 改善提案
[網羅的な改善ポイントを列挙]

### 所見
[自由記述。全体を通した所感や追加観察]
```

### 出力ルール

- 各問題点は独立したセクションとして記述する
- 該当箇所はファイルパスと行数を明記する
- 提案は具体的で実行可能な内容とする
- 全項目に問題がない場合は「該当なし」と明記する
- 全体評価は1〜2文で簡潔にまとめる
