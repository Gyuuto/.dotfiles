# Project Structure Validation

プロジェクト構造の検証スキル。ファイル配置の整合性確認とルール準拠チェックを行う。

## Purpose

- プロジェクトディレクトリが期待された構造に従っていることを確認する
- ファイルの配置が適切なディレクトリに含まれていることを検証する
- 命名規則、スタイルガイド、AGENTS.mdのルールへの準拠をチェックする
- 構造的な問題や非効率な配置を特定し、修正案を提示する

## Trigger

以下のいずれかのケースで実行する:

- プロジェクトの新規作成またはリファクタリング後
- 新規ファイル・ディレクトリの追加後
- リポジトリ構造に関する質問があった場合
- CI/CDパイプラインやビルドシステムがファイル配置を前提としている場合

## Steps

### 1. プロジェクトのディレクトリ構造を取得する

- `tree` コマンド、または同等の方法でプロジェクト全体の構造を取得する
- 対象から `.git` ディレクトリを除外する
- 出力は構造化されたリストとして保持する

### 2. AGENTS.mdからプロジェクトのルールを確認する

- ルーティングルール（ファイル配置の基準）を読み取る
- 命名規則（snake_case など）を読み取る
- スタイルガイドを読み取る
- 必須・推奨のディレクトリ一覧を抽出する

### 3. 検証を実行する

以下の項目についてチェックする:

- **必須ディレクトリの存在確認**
  - `src`（ソースコード）、`tests`（テスト）、`docs`（ドキュメント）、`rules`（ルール）、`skills`（スキル）が存在するか確認する
  - プロジェクト種に応じた追加ディレクトリが存在するか確認する

- **ファイル配置の整合性**
  - ソースコードファイルが `src` 以下に配置されているか
  - テストファイルが `tests` 以下に配置されているか
  - ルール定義が `rules` 以下に配置されているか
  - スキル定義が `skills` 以下に配置されているか
  - ドキュメントが `docs` 以下に配置されているか
  - 設定ファイルがルートまたは適切なディレクトリに配置されているか

- **命名規則の準拠**
  - ファイル・ディレクトリ名が `snake_case` で記述されているか
  - 例外ルール（言語固有の命名慣習等）があればそれに準拠しているか

- **重複・不要ファイルのチェック**
  - 同一内容のファイルが複数ディレクトリに存在しないか
  - 一時ファイル、バックアップファイル、不要なログファイルが残っていないか
  - 想定外のファイルが配置されていないか

- **ドキュメントの隣接確認**
  - モジュールに対応するドキュメントが隣接または `docs` 以下に存在するか
  - README が適切な階層に配置されているか

- **.gitignore の確認**
  - 依存関係ディレクトリ（`node_modules`, `venv` など）が除外されているか
  - ビルド出力（`dist`, `build`, `target` など）が除外されているか
  - 機密情報（`.env`, 認証情報ファイル等）が除外されているか
  - OS 固有ファイル（`.DS_Store`, `Thumbs.db` など）が除外されているか

### 4. 問題を特定し、修正案を提示する

- 各問題について、以下の情報を記録する:
  - 問題の深刻度（Critical / Warning / Info）
  - 問題の説明
  - 問題の原因
  - 具体的な修正案（移動先パス、リネーム案など）

### 5. 推奨されるディレクトリ構造を提示する

- 理想的なディレクトリ構造を図またはリスト形式で提示する
- 修正後の状態を具体的に示す

## Output

検証レポートを以下の形式で出力する:

```markdown
# Project Structure Validation Report

## Summary
- 総ファイル数: N
- 総ディレクトリ数: N
- 問題数: N (Critical: N, Warning: N, Info: N)

## Issues

### [Critical / Warning / Info] 問題タイトル
- **場所**: `path/to/problem`
- **説明**: 問題の詳細
- **修正案**: 推奨される修正方法

## Recommendations

### 推奨ディレクトリ構造
```
project-root/
├── src/
│   ├── module1/
│   └── module2/
├── tests/
├── docs/
├── rules/
├── skills/
├── .gitignore
└── AGENTS.md
```

### 実施すべきアクション
1. 優先度順の修正タスク一覧
2. 各タスクの詳細と実行方法
```
